# Y.Mine 路线图 · 从原型到发布

> 最后更新：2026-08-08

## 阶段总览

```
Phase 0 补缺口 ─┐
                ├─→ Phase 1 工程化 ─→ Phase 2 反馈验证
                │                         ↓
                └───────────────────→ Phase 3 数据层 ─→ Phase 4 打磨
```

- Phase 0 与 Phase 1.1/1.2 可并行
- Phase 2 依赖 1.3（埋点上线）
- Phase 3 独立大块
- Phase 4 可穿插在任意阶段

---

## Phase 0 · 补功能缺口（→ M1 · 9/9 完整）

### 0.1 ChessPage 国际象棋局
- **现状**：仅展示四维度映射数据，无交互
- **任务**：落子交互 + 棋风人格推导（E/I·N/S·T/F·J/P → 向量）+ 接入 personaFusion
- **依赖**：四维度映射规则已定义（见 project_memory）
- **验收**：能完成一局棋风采集，输出棋风向量，融入调酒推荐
- **风险**：完整棋局 AI 复杂度高，考虑用关键节点选择式交互降级

### 0.2 ExplorePage 五维内容深化
- **现状**：5 维度（产品/商业/金融/合作/业务）为泛占位文案
- **任务**：替换为真实白皮书/商业计划书/财务模型/合作手册/技术架构
- **依赖**：⚠️ **需要用户提供真实业务信息** —— 内容来源在用户
- **验收**：每维度有实质可读内容，非占位

---

## Phase 1 · 工程化降债（→ M2 · 可发布质量）

### 1.1 chunk 拆分
- **现状**：单包 1.6MB，build 持续警告 >500kB
- **任务**：路由级 `React.lazy` + 引擎 `manualChunks`（timeEngine/cocktailEngine/feedbackEngine 分包）
- **依赖**：无
- **验收**：首屏 <500kB，build 无警告

### 1.2 错误边界 + Suspense
- **依赖**：1.1（lazy 后必须有 Suspense）
- **任务**：ErrorBoundary 组件 + 各路由 fallback 加载态
- **验收**：局部崩溃不白屏，有加载态

### 1.3 监控埋点上线
- **现状**：trackFeedback 各节点已定义但只 console.debug
- **任务**：接真实上报通道（选型：自建 / Sentry / 其他）
- **依赖**：无（但需决定后端）
- **验收**：DEV 全量、线上 1% 采样、error 级始终输出
- **风险**：需选上报后端

---

## Phase 2 · 反馈回路闭环验证（→ M3 · 数据驱动决策）

### 2.1 反馈数据积累
- **依赖**：Phase 1.3 上线后才能采集
- **任务**：等 feedbackHistory ≥50 条
- **验收**：数据量达标

### 2.2 A/B 实验框架
- **依赖**：2.1
- **任务**：分桶哈希 + 实验配置 + timeEngine `getDynamicVector` 注入点
- **验收**：能跑时间生物学校准的对照实验

### 2.3 校准效果验证
- **依赖**：2.2
- **任务**：实验组/对照组评分差异分析
- **验收**：数据支撑"校准是否真提升评分"，决定保留/回退

---

## Phase 3 · 数据层升级（→ M4 · 产品化）

### 3.1 后端 API + 用户系统
- **任务**：登录 + 数据持久化 + 跨设备同步
- **依赖**：技术栈选型（FastAPI / Node / Supabase）
- **风险**：最大工程量块
- **验收**：登录后数据跨设备一致

### 3.2 真实内容库
- **依赖**：3.1
- **任务**：调酒配方库 / 香氛分子库替换硬编码，可后台维护
- **验收**：配方后台可增删改

---

## Phase 4 · 体验打磨（→ M5 · 发布级，可穿插）

- 4.1 页面过渡动画（路由切换 fade/slide）
- 4.2 微交互一致性（hover/active 反馈）
- 4.3 移动端适配全量检查
- 4.4 性能（首屏 LCP、动画帧率）

---

## 里程碑

| 里程碑 | 含义 | 前置 |
|---|---|---|
| M1 | 9/9 功能页完整，全链路可演示 | Phase 0 |
| M2 | 可发布质量，无白屏，埋点就位 | Phase 1 |
| M3 | 数据验证校准有效 | Phase 2（需真实用户） |
| M4 | 支持多用户产品化 | Phase 3 |
| M5 | 发布级体验 | Phase 4 |

---

## 关键风险

1. **ExplorePage 内容来源在用户** —— Phase 0.2 阻塞，需用户提供真实业务信息
2. **Phase 2 需要真实用户** —— 反馈数据要发布后才能积累，M2 发布是 M3 前提
3. **Phase 3 后端选型** —— 影响工程量，建议 M2 后再决定是否需要
4. **ChessPage 棋局 AI 复杂度** —— 完整国际象棋 AI 过重，倾向用关键节点选择式交互
